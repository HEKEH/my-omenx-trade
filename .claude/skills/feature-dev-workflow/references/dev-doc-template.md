# 开发文档（开发参考）骨架模板

> 通用骨架。核心是 **§5 字段映射**——把「需求点 ↔ 设计图节点 ↔ 接口字段」三方对齐落到表里。项目里已有同类文档时可沿用其风格，但 §3 需求覆盖表与 §4 证据表建议保留。

```markdown
# <需求名> — 开发参考

> **用途**：把 PRD / 评审记录 / Figma / 接口对齐成一份可引用的实现说明。
> **基线**：复用了哪些已有模块（组件 / hook / service / 类型 / 路由），沿用哪些既有约定。
> **整理日期**：<YYYY-MM-DD>

## 1. 功能定位与入口

| 项             | 说明                                  |
| -------------- | ------------------------------------- |
| 功能定位       | …                                     |
| 入口           | 路由 / 触发方式 / 平台限制（PC / H5） |
| 与现有模块关系 | 复用 / 新增 / 冲突点                  |

## 2. 分区 / 模块总览

| 小节 | 区块 | 布局（按 Figma 节点） | 数据来源接口 | Hook     |
| ---- | ---- | --------------------- | ------------ | -------- |
| §5.1 | …    | … `node-id=…`         | `GET /…`     | `useXxx` |

## 3. 需求覆盖表

> PRD 拆出来的每个需求点占一行，四列都要填满；「里程碑」列必须指向路线图里真实存在的里程碑。写完路线图后逐行核对，防止需求点漏做。

| 需求点       | 设计节点    | 接口                  | 里程碑 |
| ------------ | ----------- | --------------------- | ------ |
| <PRD 的一条> | `node-id=…` | `GET /…` → `data.xxx` | M2     |
| <不涉及接口> | `node-id=…` | 无                    | M3     |

## 4. 证据表

> 凡涉及判断的地方都用它，一行一个**可独立验证**的断言。**推断必须显式标注**，不能与事实混排；**截图只证明外观**，不证明组件身份或行为；**文件名只证明存在**，不证明这条代码路径是活的。

| ID   | 断言                     | 证据                       | 影响         | 状态                         |
| ---- | ------------------------ | -------------------------- | ------------ | ---------------------------- |
| E-01 | <某字段的顺序由接口决定> | `service/x/index.ts:142`   | 决定渲染顺序 | verified                     |
| E-02 | <空态设计稿未画>         | Figma `node-id=…` 无该节点 | 需产品确认   | blocked                      |
| E-03 | <推断：沿用既有 xx 约定> | 仓库 3 处同类写法          | 影响命名     | inferred（未验证，标注在此） |

## 5. 各分区数据与字段映射（核心）

> 每个区块一张表：需求点 → Figma 节点 → 接口字段 → 组件 props/展示。凡有疑问处标 ⚠️ 并已与用户对齐。

### 5.1 <区块名>（Figma `node-id=…`）

| 需求点 / 展示项 | Figma 节点 | 接口字段（path.schema.field） | 组件 props / 处理 | 备注 |
| --------------- | ---------- | ----------------------------- | ----------------- | ---- |
| …               | …          | …                             | …                 | …    |

## 6. 接口清单

| path | method | 入参 | 返回 schema（关键字段） | 对应 hook | 备注 |
| ---- | ------ | ---- | ----------------------- | --------- | ---- |

## 7. 类型定义指引

- 新增 / 复用的 TS 类型及所在文件。

## 7b. Mock 方案（仅当决定用 Mock 时保留本节）

- mock 数据文件：`<path>`（覆盖哪些关键形态）。
- 开关常量：`<FEATURE>_USE_MOCK`（默认 `false`，本地调试改 `true`），位置 `<path>`。
- service/hook 接法：`USE_MOCK ? mock<X>() : apiClient.get<X>(...)`（真接口后置到联调期关开关）。

## 8. 交互与跳转约定

- 点击 / 跳转 / 参数（如 `?a=x&b=y`）/ 状态分支 / 空态与边界。

## 9. 风险与待定项

| 风险 / 待定 | 影响 | 处置 / 已对齐结论 |
| ----------- | ---- | ----------------- |

> **已对齐结论**写在这一列：用户每回答一个疑问就立刻落盘。口头澄清是上下文压缩后最先消失的信息，不落盘等于没问过。
```
