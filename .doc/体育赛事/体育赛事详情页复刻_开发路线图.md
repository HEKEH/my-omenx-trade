## 0. 原则与约束

- **范围（开发参考 §0）**：只做 `/sports/event/[id]`。B-1 全部赛事；B-2 仅桌面；B-3 源 bug 原样复刻，登记在开发参考 §4.2；B-5 直播只做占位。
- **分层与依赖方向（B-4）**：`presentation → application → domain`，`infrastructure` 提供数据；domain 不 import 其他层，也不依赖 React、Next 或浏览器 API（开发参考 §7.2）。组件和 hooks 里不写业务公式，一律调用 domain 函数。
- **没有真接口（E-02）**：数据走 infrastructure 的 mock 仓储（开发参考 §6），路线图里**没有**「真接口联调」里程碑。
- **不影响 trade 页**：`src/modules/trading`、`src/components/ui` 不改。改动根布局时，trade 页的 URL、样式和行为都不能变（R-1），每次动到 `src/app` 都要回归 trade 页的检查脚本。
- **class 照源项目写**：两边都是 Tailwind 4（E-04），源 class 可以直接用；颜色走 sports token，不写死（源代码里本来就写死的颜色照抄，例如 `OrderBook` 的 oklch 值、AIRDROP 的 purple）。
- **Next 16**：写路由、布局、metadata、not-found 之前，先读 `node_modules/next/dist/docs/` 里对应的章节（AGENTS.md 的要求）。
- **测试（B-4）**：domain 每个模块都先写测试并跑到红，再实现到绿。Vitest 的 include 扩展到 `src/modules/sports/domain/**/*.test.ts`。
- **像素对齐**：每个 UI 里程碑内部都要用浏览器实测一轮（参照页 :8081，本项目 :3000，视口 1440×900 和 1920×1080，脚本冻结 `setInterval`，见 R-3）。逐节点精修统一放到 M9。
- **每步循环**：开发 → 自查 → `pnpm exec tsc --noEmit` 0 错误 + `pnpm lint` 通过（涉及 domain 或数据时再加 `pnpm test`）→ 打钩 → commit（`feat: ...` 风格，结尾加 Co-Authored-By）。**UI 里程碑结束时再跑一次 `pnpm build`**。用户自己的未提交改动不纳入提交。
- **SSR 一致性**：首屏只依赖 market.id 能确定的数据（种子、tick 0）。`Date.now()` 和定时器只在 `useEffect` 里使用（R-4）。
