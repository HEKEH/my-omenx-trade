# 体育赛事详情页复刻 — 开发参考

> **用途**：把源项目 `C:\Users\hekai\Desktop\Archive\omenx-sports` 的赛事详情页 `/event/$id` 复刻到本项目的 `/sports/event/[id]`，作为可引用的实现说明。除直播画面外，页面要与源项目一致。源代码只作参考：业务代码按本项目的 DDD 分层重写，不整份照抄。
> **范围**：只做赛事详情页。首页、赛事列表、联赛页、Fans、样式指南等其他路由一律不做。
> **基线**：
> - **本项目**：Next 16.3.6（App Router）+ React 19.2 + Tailwind 4 + TypeScript + zustand + Vitest。已有 `/trade` 模块 `src/modules/trading`（DDD 分层），通用 UI 原语在 `src/components/ui/`，这些原语是按 trade 页样式调过的版本。
> - **源项目**：TanStack Start（Vite）+ React 19 + Tailwind 4 + shadcn（new-york，`@radix-ui/react-*`）+ recharts 2.15.4 + lucide-react 0.575.0 + sonner。
> **整理日期**：2026-09-25
> **源码引用约定**：`src/...:行号` 均指源项目 `omenx-sports` 下的路径。参照页运行在 `http://localhost:8081`。

| ID | 风险 / 待定 | 影响 | 处置 / 已对齐结论 |

| R-12 | 跳到另一个赛事时，源项目（TanStack Router）是同一个路由组件继续挂载：持仓、挂单、历史通过 effect 重置，但 `selectedIdx`、`multiTradeSide` 会保留（`event.$id.tsx:287,305,339-344`）。Next App Router 在动态参数变化时会不会保留客户端 state，还没有实测 | 从相关赛事跳转后，选中的结果可能与参照页不同 | M8 先在参照页和本项目上分别实测，再让本项目的行为与参照页一致（B-3） |
| R-16 | 依赖版本与源不一致（E-23） | 可能出现 DOM 或样式上的细小差异 | 走查时发现差异就锁定到源项目的版本；只影响 sports 时，用 npm 别名，不动 trade 页的依赖 |
| R-13 | Next 16：页面的 `params` 是 Promise，要 `await`；可以用全局类型 `PageProps<'/sports/event/[id]'>` 取得强类型的参数 | 页面和 `generateMetadata` 的写法 | 照文档写（`03-file-conventions/page.md:125-140`） |
| R-14 | Next 16.3：`error.tsx` 必须是 Client Component，props 是 `{ error, retry }`（`retry` 在 16.3 转为稳定 API，会重新请求并重新渲染该段）；`reset` 只清除错误状态、不重新请求 | 源错误页的 Retry 按钮是 `reset()` 加 `router.invalidate()`，等价于 `retry()` | 用 `retry()`（`03-file-conventions/error.md:120-160,327-333`） |
| R-15 | `notFound()` 可以在 `generateMetadata` 里调用；`not-found.tsx` 渲染在所在的根布局里；多个根布局时，完全匹配不到的 URL 要靠实验特性 `global-not-found.js` 来渲染 404 | R-11 | 见 R-11（`03-file-conventions/not-found.md`、`04-functions/generate-metadata.md:197`） |
