## 1. 功能定位与入口

| 项 | 说明 |
| --- | --- |
| 功能定位 | 预测市场交易终端：选择事件和选项，查看 K 线与盘口，按 1–10x 杠杆开 Yes/No（多头/空头）仓位，管理持仓和委托。 |

### 7.2 计算规则（口径以服务端为准，A-3）

> **精确小数（M1 复查后补充）**：SQL 用 `numeric` 做精确小数运算，JS 浮点会在 .5 处舍错（例如 `0.35 / 0.1 = 3.4999…`、`0.005 × 2913 / 3 = 4.8549…`）。所以合约数、保证金、手续费、名义价值、潜在收益一律换成整数单位再算：价格按 1e-4、金额按分，最后用「整数除法 + 四舍五入」（`shared` 的 `toUnits` / `divRoundHalfUp` / `feeFor`）。输入的金额按分取整，价格必须是 4 位小数，否则 `validateOrder` 报 `invalid-price`。

| 计算 | 公式 | 舍入 | 源 |
| --- | --- | --- | --- |
| 侧价格 | 多选项：Yes = p，No = round4(1−p)；二元：取所选选项自身的价格 | 4 位 | `DesktopTrading.tsx:369-388` |
| 合约数 quantity | `round(amount × lev / price)`（四舍五入成整数，SQL 要求必须是整数） | 取整 | `:412` + SQL :196-202 |
| notional | `price × quantity` | 2 位 | SQL 口径 |
| 保证金 margin | 开仓或加仓时 `round2(price × qty / lev)`；减仓或平仓时为 0 | 2 位 | SQL :224 |
| 手续费 fee | `round2(price × qty × 0.0005)` | 2 位 | SQL :222（FIX-2） |
| total | `margin + fee` | 2 位 | `:409` |
| potentialWin | `(1 − price) × qty` | 取整 | `:415` |
| 强平价 | `clamp01(entry × (1 − 0.9 / lev))`；entry 是仓位所在侧的价格（FIX-7） | 4 位 | `tradingUtils.ts:76-94` + FIX-7 |
| 意图分类 | 完整移植 `classifyOrderIntent`：EPSILON 1e-6；二元事件净额（买 No@p = 以 1−p 平 Yes）；FIFO 逐笔释放保证金、计算已实现盈亏（扣除分摊的资金费）；不允许一笔订单跨过零（blocked-cross-zero）；遇到空投或历史冲突时 blocked-market（本项目没有空投，只保留冲突判定） | — | `positionIntent.ts:69-199` |

## 8. 交互与跳转约定

- **事件选中**（源 `useEvents.ts:274-313`）：优先取 `?event=`；否则取 localStorage `trading_last_event`；再否则取第一个事件。如果 `?event=` 指定的事件不存在 → 显示「事件已结束」兜底页。切换事件时用 `router.replace('/trade?event=<id>')`（源 :339 `navigate(..., {replace:true})`）。只有这一个 URL 参数。
- **选项选中**（源 `useEvents.ts:321-332`）：localStorage `trading_last_option` = `{[eventId]: optionId}`，存的选项仍然有效就用它，否则用 `options[0]`。
- **盘口行点击** → 切到 Limit，并填入该行价格。
- **下单**：点提交 → 订单预览弹窗 → 确认 → `PlaceOrder` → toast → 通过 realtime 刷新持仓或委托。
- **委托行 HoverCard** "Go to this event" → 切换事件。
- **ExpiredEventFallback 的两个按钮**、**No events 的 Return to Home**：目标页面不在范围内，行为见 §9 R-3。
- **键盘/焦点**：Radix 原语自带的 Esc 关闭、焦点陷阱保持不变。
