## 0. 原则与约束

- **分层与依赖方向**：`presentation → application → domain`，`infrastructure` 实现 application 的端口；domain 不 import 任何其他层，也不依赖 React、Next 或浏览器 API（开发参考 §7.1）。
- **计算只写在 domain**：组件和 hooks 里不写业务公式，只调 domain 函数（开发参考 §7.2）。
- **全量 mock（A-7）**：没有真接口，因此路线图里**没有**「真接口联调」里程碑。mock 服务端保持 supabase-js 的调用形状，将来接真 Supabase 时只需替换 `infrastructure/container.ts` 里的装配。
- **组件库（A-11）**：通用 UI 原语用 shadcn/ui 生成，样式对齐源项目；业务代码自己写，不照抄源码。
- **Next 16**：写路由、页面、字体代码之前，先读 `node_modules/next/dist/docs/` 里对应的章节（项目 AGENTS.md 的要求）。`/trade` 页面是 Client Component，`searchParams` 用 `useSearchParams()` 读取。
- **测试（A-5）**：domain 的每个模块都先写测试并跑到红，再实现到绿；Vitest 只覆盖 `src/modules/trading/domain/**`。
- **像素对齐（A-6）**：每个 UI 里程碑内部都要用 chrome-devtools 做一轮实测对齐（源项目 `pnpm dev` 跑在 :8080，本项目跑在 :3000，视口 1440×900 和 1920×1080 各量一次）；逐节点精修统一放到 M10。
- **每步循环**：开发 → 自查 → `pnpm exec tsc --noEmit` 0 错误 + `pnpm lint` 通过（涉及 domain 时再加 `pnpm test`）→ 打钩 → commit。commit message 沿用仓库风格（`feat: ...`）。**UI 里程碑（M4 起）结束时再加跑一次 `pnpm build`**：有些问题只在预渲染时才暴露，开发模式下看不出来（例如 `useSearchParams` 没有包 Suspense，见 Next 文档 `use-search-params.md:82-88,180`）。
- **只在客户端运行 mock**：mock 服务端、行情流、定时器和 localStorage 都只能在浏览器端启动（放在 `useEffect` 里）。服务端渲染只输出 Loading 状态，避免随机数据和 `Date.now()` 导致 hydration 不一致。

## 4. 风险与阻塞

| 风险 | 影响里程碑 | 处置 |
| --- | --- | --- |
| chrome-devtools MCP 需要重启会话才生效；在 Windows 下直接用 `npx` 启动可能起不来 | M4–M11 | 进入 M4 前重启会话，并先调一次 `list_pages` 确认可用；起不来就改成 `cmd /c npx chrome-devtools-mcp@latest` |
| shadcn CLI 生成的 Tailwind 4 版本样式与源项目的 Tailwind 3 版本不一致 | M0、M10 | M0 逐个组件对照源码修正，M10 实测兜底 |
| Tailwind 4 下 `hsl(var(--x) / <alpha>)` 的透明度写法与 Tailwind 3 不同（源项目大量用 `border-border/30` 这种写法） | M0、M4 | M0 迁移 token 时，按 Tailwind 4 的 `--color-*: hsl(var(--x))` 写法做，并实测 `/30` 透明度是否生效 |
| 源项目参照页是未登录状态，持仓区模糊、风险卡不显示 | M9、M10 | R-1：去掉 blur 后再量；风险卡按源码 class 核对并标注 |
| 随机 mock 数据导致对齐时数值不断变化 | M4–M11 | 固定随机种子 + `__tradeMock.freeze()` / `NEXT_PUBLIC_TRADE_MOCK_FREEZE`；源项目那边没有冻结手段，只比结构和尺寸 |
| 随机数据、定时器、localStorage 在服务端渲染时执行，导致 hydration 不一致 | M4 起 | §0「只在客户端运行 mock」+ `TradeMockProvider`；每个 UI 里程碑都用 `list_console_messages` 检查 |
